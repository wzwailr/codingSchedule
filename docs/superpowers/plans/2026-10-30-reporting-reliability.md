# AI进度汇报可靠性改进方案

日期：2026-10-30。状态：连接恢复、精确回执归并、连续显示进度/ETA与贴边隐藏已实施，验收记录见[本轮报告](../../verification/reporting-reliability.md)。短checkpoint、限次异步提醒与扩大真实宿主样本仍为后续范围；不能把本轮实现视为整个可靠性计划关闭。耐久保持停止。

## 要解决的事实

用户的标准是“正在看的真实会话能看到当前动作、可靠计划及最近有效ETA”，不是报告接口返回成功。

初次核查：本聊天旧MCP工具返回`Transport closed`；本地begin／context／report成功，但当时实际数据库来源关联和窗口未闭环。修正证据口径：raw context本身不附加listSnapshots的关联字段，不能只凭字段缺失判断未绑定。本轮回执归并已在来源表、活动投影和原生窗口共同核对；旧连接关闭与fallback报告未绑定是两个独立问题。

源码线索：`src/adapters/common/reporter-binding.ts`只识别真实begin／context调用，或包含明确progress工具调用的code-mode包装。当前`node_repl → sendLocal`降级路径不属于该关联入口。没有绑定的reporter任务也没有原生in-flight证据；有界活动投影可能在三分钟无工作报告后移出活动列表。仅修改“请经常汇报”提示词不能解决这些链路问题。

已有Skill、默认用户规则、原生日志、Hook和ETA协议继续复用，不再造另一套进度系统。所有新设计都必须保留：只操作原任务、未知不造百分比、有效ETA持续倒计时、等待冻结、省略或null不清空、AI完成与人工验收区分。

## 推荐实现顺序

| 顺序 | 改什么 | 验收结果 |
| --- | --- | --- |
| 1：连通与归并 | 把接入状态分成服务可达、当前宿主工具可用、报告接收、精确会话已关联四项。为受支持的本地降级入口设计可验证回执；精确绑定到发起调用的原session／turn。 | 不再以SDK成功冒充当前聊天可用；MCP断开／降级后，正确会话显示真实计划，无重复会话。 |
| 2：降低模型负担 | 增加可选的轻量checkpoint入口，复用context／report协议，在本地完成序号读取、幂等与短回执；保留现有四工具。接收宿主已有原生计划工具的明确步骤变化。 | 模型用一次短动作更新即可；计划未知仍未知，冲突不覆盖外部变化；测量真实token差异再给节省结论。 |
| 3：规则和异步提醒 | Skill明确开始、实质进展、等待／恢复、阶段变化、结束五类触发。受支持且已信任的Hook只在原会话自然工具边界投递短提醒。 | 漏报得到一次轻提示，正常汇报不被打扰；不在用户聊天刷屏，不唤醒闲置／其他会话。 |
| 4：诚实兜底 | 独立展示原生观察的新鲜度与语义计划的新鲜度；后台检测缺口，显示“活动已检测，尚未收到计划／汇报待关联／连接需重连”等可解释状态。 | 模型漏报时仍有真实动作，不制造进度／ETA，不把等待或过期当失败。 |
| 5：端到端验收 | 在真实Codex和Claude桌面Code上跑正常、遗漏、断开、重启、压缩上下文、并行会话等样本。 | 从实际宿主调用到归并后的悬浮框一起验；接口、DOM和单宿主成功不代替完整链路。 |

先做1、2，再做3，最后扩大真实样本。不要先堆更多提示语或额外定时询问模型。

## 1. 连通和绑定怎样做

- 开始时读取已有能力和错误，失败只给一次诊断并继续业务；不能重试刷屏、重装服务或自动改宿主配置。悬浮框详情／设置显示接入状态，微型态保持简短状态提示，不增加面板。
- 关联凭据只能来自宿主实际session／turn／tool-call元数据和受信任本地服务回执，不能按cwd、窗口焦点、标题或最新任务猜测。私有resumeHandle只留在原agent上下文，不进入日志、UI或子agent。
- 降级回执需要校验所属connector、runId／generation、调用相关性、时效和重复使用；单独出现`codingScheduleBinding`字符串不能成为新的授权依据。旧版本、失败调用、归档重放、跨会话复制、同目录并发和已占用绑定必须有拒绝测试。具体回执格式先做安全评审，再实现解析／存储与来源关联。
- 当前整个桌面进程退出会关闭其共享SDK连接。短期明确提示宿主重新连接；不能假称桌面重启后旧stdio自动复活。若后续实现自动恢复，应保持宿主侧MCP生命周期、重新完成后端握手，并将不确定ACK当幂等恢复问题处理，不能盲目重放写操作。不要为此退回每个MCP实例各起一份Node／SDK；重新跑三实例完整进程树内存门禁。

建议文件范围：`src/bridge/{transport,broker,native-relay}`、`src/adapters/common/reporter-binding.ts`、精确来源关联存储与对应负面测试；只修改实际采用的恢复方案，不把多个候选架构都塞入产品。

## 2. 让模型少做步骤

目前一次更新通常需要模型先context，再组织序号、UUID、changes，且返回上下文较长。建议增加兼容入口，把本地机械步骤封装起来，模型只提交“动作／步骤变化／等待或恢复／可选新估时”，服务仍用现有领域协议校验。

checkpoint不自动重写计划，不自动补齐未知步骤，也不让后台替原agent编ETA。发生竞争或计划版本冲突时返回短诊断，由原agent判断。丢ACK只允许同ID、同body恢复。开始、结束等语义状态仍需真实agent声明；宿主工具调用次数不能映射为完成百分比。

原生计划已经存在时，优先解析宿主本来就发出的明确计划工具，避免要求模型重复写一份。完整计划范围不明则仅展示动作和已知步骤，保留进度未知。

## 3. 提醒与估时策略

启动／恢复／压缩上下文后提供一段短规则：保留自己的句柄；按实质节点汇报；结束前对账。正常动作变化、开始测试／得到结果、切换阶段、进入／离开等待时报告；不规定每条聊天、每个工具或每次思考都写报告。

建议Hook门控参数仅作为待验证初值：业务工具边界出现新的实际活动、距离最近语义汇报超过90秒且无待投递提醒时，排队一次短提醒；同一缺口冷却至少2分钟、每任务最多3次。等待／暂停、无新增活动、已结束或通道不可用时不提醒。排除progress工具和Hook自身，防止自触发循环。这是事件边界门控，不是定时轮询ETA，也不能覆盖单次长工具执行内部。

只通过原会话支持的异步上下文入口投递，不使用聊天消息、跨会话发消息、采样另一个模型或唤醒机制。默认不使用阻塞Stop来逼模型补报，也不使用asyncRewake；结束时发现缺口只记录真实未闭环状态，主任务不被遥测卡住。

ETA只在首次可估时给一次；此后只有范围需要修正才通过可选etaUpdate提交。普通进度不附带重复ETA，窗口沿用最近有效值。可选提醒应明确“只补当前动作／步骤变化，若估时未变无需重复”。

## 4. 宿主能力与边界

Codex官方说明支持异步命令Hook：活动轮次在安全点接收信息，无活动轮次不会因后台Hook自行开启；Hook定义变更需重新信任。采用`additionalContext`，避免用会向用户展示警告的`systemMessage`作常规提醒。异步Hook不能控制已发生的操作，也不保证模型一定遵从。[Codex Hooks](https://learn.chatgpt.com/docs/hooks)

Claude Code官方说明覆盖桌面Code等入口，异步命令Hook可在后续会话边界交付上下文，不能阻塞或强制控制原操作；独立CLI账户状态与桌面会话仍分开验收。本方案不用可唤醒机制。[Claude Code Hooks](https://code.claude.com/docs/en/hooks)

通用MCP没有统一的宿主Hook保证，先使用Skill和自然工具取件；宿主不支持原agent私下接收上下文时，明确降级。插件可以打包Skill／MCP／Hook，但安装插件不等于执行环境已有脚本或Hook已被信任。[OpenAI插件打包说明](https://developers.openai.com/plugins/build/plugins)

以上是官方支持边界，不是本机新提醒机制已通过。实施前核对真实宿主版本和可用能力；本次未安装／改写这些配置。

## 5. 验收指标与样本

以下是建议验收目标，不是已经达到的指标：

- 确定的归并与安全样本：正确session／turn对应100%通过，串会话0例；拒绝伪造、复制、重放、过期和失败回执。
- 每宿主至少30条真实多步骤任务：开始／结束闭环率及实质节点汇报覆盖率目标≥95%。每条记录调用证据、投影结果、是否需要提醒和失败原因，不能只数模型自称已汇报。
- 已收到合法报告后，正常本地投影延迟目标≤5秒；尚在思考或长工具内部时只报告真实原生活动，不能承诺模型按秒语义汇报。
- 同目录双会话、后台并行、用户手选／自动跟随、MCP断开、桌面替换、丢ACK、会话压缩／恢复、Hook未信任／不支持、等待、无ETA与null、新估时、取消／中断都覆盖。人工输入与焦点保持需独立原生验证。
- 额外token和调用数实测；正常任务不重复给ETA，不引入周期模型调用。提醒只发原会话；主任务中断、自动唤醒、重复进度会话为0。
- 重新验完整进程树内存与数据库预算；不因可靠汇报退回多SDK实例。耐久另按用户明确安排，当前保持关闭。

无法对任意第三方宿主保证模型100%照做。可做到的是让机械采集和绑定可验证、减少模型要记住的步骤、在安全边界有限提醒，并把未报告与链路失败诚实展示。
