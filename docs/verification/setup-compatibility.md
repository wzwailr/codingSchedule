## 配置兼容

真实预检发现：两宿主的旧汇报规则缺少安装回执，因内容与新模板不同被误判冲突；已有效的 MCP 和 Claude Hook 主要是包路径不同。

- 一键接入保留兼容的 MCP / Hook 原文件，不重写 command、args、审批字段、环境变量、注释或其他配置。核对本地入口文件内容和角色、凭据/endpoint 路由；Hook 只解析本工具生成的引号参数格式，同时核对脚本与 common.cjs，不执行配置里的 shell 命令。
- 文件比较使用 64KiB 流式散列和有界缓存，避免一次读入两份 Node 二进制造成内存峰值。
- 已有完整 codingSchedule 标记块、标准标题及汇报 Skill/context 引用的旧默认规则可以沿用；已有回执却被修改的规则继续保留并提示核对，不覆盖用户修改。仅换行不同的同一 Skill 原样保留；未知同名 Skill、外部凭据路由、禁用配置和坏格式继续拒绝覆盖。
- 沿用的组件不新增安装回执，整体撤销只撤销本次管理的内容；原有受管组件仍按原回执安全撤销。既有备份和未完成事务恢复继续有效。
- 配置齐全只说明接入材料齐全，不保证宿主已重新加载或模型每次自然调用；不重启 AI 宿主，不改变审批权限。

## 手动关联

- 移入默认收起的“高级设置”，仅在自动关联失败时使用。任务与会话标签区分“正在汇报的任务”“正在活动的会话”，空态有明确提示并禁用提交。
- 与主悬浮框共用活动投影：过滤暂停、完成、取消、已过期和被新轮次替代的记录。没有关联证据时不按标题或目录猜测归并。真实未返回的工具调用与仍有原生活动的等待任务按原有策略保留。
- 设置保持打开时，快照变化和本地时钟会更新下拉框；新原生轮次出现或用户展开高级设置时才读取来源，不按秒查询后台。选项未变化时不重建，选择仍有效就保留；提交前保留用户原选择并复核，结束时不悄悄改关联另一个会话。
- 主进程也重新核对两端的当前活动状态及 generation，拒绝陈旧或结束任务；worker 仍负责来源归属与完整回放校验。
- 清理原先独立、静态且只排除终态的历史列表路径，以及引导用户必须手动关联的旧文案。
