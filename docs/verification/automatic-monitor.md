# 默认自动监测与高级手动维护

2026-11-03，本地 v41。针对“为什么还要选择 AI”的界面误导，保留同时监测 Codex / Claude 的采集行为，调整设置层级；不改宿主配置、不启动耐久、不推送发布。

- 原“AI 工具”选择器仅决定手动预览/修改哪份接入配置，不控制后台监测来源。它与日志路径、监测开关一起收进默认关闭的高级设置，改名“配置目标（仅手动维护）”。手动关联仍在高级设置内。
- 默认首先显示“自动监测”与两来源的真实启用状态。两来源开启时明确“同时监测 Codex 和 Claude，无需选择 AI”；没有活动显示空闲，活动会话自动出现和跟随。状态不把“开启”冒充“会话正在运行”或“采集没有故障”。
- 保留用户关闭某一来源的选择，不因接入安装或切换手动配置目标强制开启。实时活动观察与 AI 上报的计划/估时分开说明。
- 普通控件先完成状态及事件初始化，再异步检查接入，避免短暂暴露未初始化的登录开关等控件。高级维护内应用/撤销后保留展开状态；新进入设置仍默认收起。

验证：类型检查、lint、生产 build、Windows 目录打包；三个相关测试文件共八项通过，覆盖两来源同时检测、选择手动目标不改变监测来源、隐藏高级控件、日志动态活动/结束过滤、手动接入及重复撤销、采集器故障重连、接入后保留来源关闭偏好。最终目录包的三个复验与八项计数重叠，不相加。原始结果在本地 `.artifacts/auto-monitor/window-tests.json`、`package-tests.json`，浅深截图在 `screens/`，静态设计扫描无发现。

本机真实来源核对为 Codex 和 Claude 均启用。不是高 DPI、多屏、物理输入或完整资源门禁扩大验收。
