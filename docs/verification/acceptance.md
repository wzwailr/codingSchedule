## 独立审阅与单次修复

独立审阅确认 4 项 Important、0 项已确认 Critical：卸载内置参数可能绕过白名单；重复接入回执可导致撤销死路；回放等待恢复指向不同任务；性能门禁忽略负载与采样覆盖。四项均补充失败回归再修复。NSIS 删除参数保护实际编译成无删除操作的探针，拒绝参数退出码由 0 变为 2；规范卸载路径不变。

重复接入现在是幂等操作，同一宿主/规范化路径只保留一个有效回执；重新配置后的回退保留后来修改的宿主字段；旧版本回执栈作为一组撤销。基准在同一 run 完成等待/恢复，再开始计时；核对全部 reporter active、预期事件数量与真实持久数量，并要求每阶段采样数量、覆盖跨度、边界缺口、最大间隔与单调性充足。短时/低负载调试不能冒充标准通过。

当时保留的 Minor 是回放只验证收到 ACK 后的同 ID 重试。2026-10-27 已补齐：真实 HTTP 代理消费 COMMIT 后 ACK，再在客户端响应头发出前断连；节点级存储测试与打包包内常驻 MCP 进程均观测网络错误。精确重试返回 duplicate，事件数核对不重复。失败回归再修复通过，不再把普通重复请求称作 Lost ACK。

审阅未覆盖的安装交互、跨登录、物理输入、完整多宿主流程、耐久和 AI ETA 质量继续保持未验收。审阅者独立跑了 15 项相关测试，实施者随后执行完整回归；审阅不是上述用户路径的替代证据。修复按失败回归和完整测试验证，没有第二轮重复审阅。
